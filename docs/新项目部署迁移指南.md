## 二、给下一个项目 AI 提供的信息

### 2.1 账号与基础设施信息（AI 无法自行获取，需人提供）

以下信息 AI 无法通过登录阿里云控制台获得，需在任务开始时一次性提供：

1. **服务器凭证**：公网 IP（同一台 ECS 即 `115.29.231.222`）、登录用户（root）、SSH 免密是否已配置（本机 `~/.ssh` 已有公钥，新项目无需重配）。
2. **阿里云控制台账号**：AI 无法登录控制台，凡涉及控制台的操作必须由人完成（见 2.4）。
3. **新域名信息**：注册好的域名、DNS 解析记录（人配置后告知）。
4. **证书文件**：申请下载后的 `.pem`/`.key` 文件路径（人上传后告知）。
5. **端口规划**：新项目后端端口（建议 3002，避开 3001）。
6. **数据库选择**：SQLite（零配置，与游子衣一致）或 PostgreSQL/MySQL（需人先在服务器安装）。

### 2.2 标准部署流程（AI 可自主完成的部分）

前提：SSH 已通、域名已解析、证书已上传。

```bash
# 1. 服务器拉取代码
ssh root@115.29.231.222
cd /var/www/<new-project>/app
git pull origin main

# 2. 安装与构建（Monorepo 顺序：共享包 → 后端 → 前端）
cd packages/types && npm install && npm run build
cd ../../apps/server && npm install && npm run build
cd ../web && npm install && npm run build

# 3. 数据库迁移
cd ../server && npx prisma migrate deploy

# 4. PM2 启动后端（注意用新项目端口与独立进程名）
pm2 start dist/index.js --name <new-project>-api
pm2 save

# 5. Nginx 新增 server block（复制游子衣配置模板改域名与端口）
vim /etc/nginx/conf.d/www.<new-domain>.conf
vim /etc/nginx/conf.d/api.<new-domain>.conf
nginx -t && systemctl reload nginx

# 6. 修复前端产物权限（关键！否则页面空白）
chown -R nginx:nginx /var/www/<new-project>/app/apps/web/dist/
chmod -R 755 /var/www/<new-project>/app/apps/web/dist/
```

本地快速热修复（替代 GitHub 拉取）：

```bash
cd apps/web && npx vite build --emptyOutDir
scp -r "apps/web/dist/*" root@115.29.231.222:/var/www/<new-project>/app/apps/web/dist/
ssh root@115.29.231.222 "chown -R nginx:nginx /var/www/<new-project>/app/apps/web/dist/ && chmod -R 755 /var/www/<new-project>/app/apps/web/dist/"
```

### 2.5 新域名接入方案对比（多域名共存与备案说明）

**结论：一台服务器可以绑定任意多个域名，推荐新域名直接指向同一台服务器，不需要新开端口。** 游子衣本身就是实例——同一台 ECS 上绑定了 `www.youziyi.com` 与 `api.youziyi.com` 两个域名，Nginx 用 `server_name` 区分。

| 方案 | 可行性 | 说明 |
|---|---|---|
| **新域名 → 同一服务器 IP（推荐）** | 标准做法 | 新域名 A 记录指向 `115.29.231.222`，Nginx 用 `server_name` 区分不同域名，80/443 端口全部复用。URL 干净，各域名证书独立 |
| 一台服务器只绑一个域名 | 错误认知 | 无此限制。Nginx 虚拟主机支持多域名共存，新项目只需新增一个 conf 文件，不碰游子衣的 |
| 新域名 + 非标准端口（如 `:8443`） | 技术可行但不推荐 | URL 变成 `https://xxx.com:8443`，不专业；微信小程序/浏览器对端口有限制；还需在安全组额外放行端口 |

**关键前提：ICP 备案（大陆服务器的硬约束）**

域名要在 80/443 正常访问阿里云大陆 ECS，必须完成 ICP 备案。未备案的域名解析过来后，HTTP/HTTPS 请求会被阿里云在运营商层直接拦截为备案提示页——不是 Nginx 层面能绕过的。

新域名正确接入顺序：

1. **注册域名 + 实名认证**（阿里云万网，几分钟）
2. **ICP 备案**（1-2 周，期间 80/443 无法访问）← 唯一的等待瓶颈
3. **DNS 添加 A 记录** → `115.29.231.222`
4. **申请免费 SSL 证书** → 在服务器新增 nginx conf + 证书，随后 `nginx -t && systemctl reload nginx`

**备案等待期的临时方案**

- 用 **`http://115.29.231.222:8080`** 这类「IP + 非标端口」访问（需在安全组放行 8080），不触发备案拦截，适合开发期自测
- 备案通过后切回标准 80/443
